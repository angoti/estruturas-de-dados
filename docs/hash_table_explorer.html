colisão

Encadeamento separado (separate chaining)

Cada posição (bucket) contém uma lista ligada de entradas. Quando há colisão, o novo elemento é adicionado à lista do bucket correspondente. No Java 8+, buckets com ≥ 8 entradas são convertidos em árvores rubro-negras.

Endereçamento aberto (open addressing)

Quando há colisão, busca-se a próxima posição livre dentro da própria tabela. Nenhuma lista encadeada é usada — todos os elementos ficam no array.

performance

Rehashing e fator de carga

O fator de carga λ = n/m (elementos / capacidade). Quando λ ultrapassa o limite (padrão 0,75 no HashMap), a tabela é redimensionada: nova capacidade = 2 × antiga, e todos os elementos são reinseridos.

hashCode() e equals() em Java

O contrato hashCode/equals é fundamental: objetos iguais (equals retorna true) devem ter o mesmo hashCode. Violar esse contrato quebra o comportamento do HashMap.

correto Implementação válida
@Override
public boolean equals(Object o) {
  if (this == o) return true;
  if (!(o instanceof Produto p)) return false;
  return id == p.id;
}
@Override
public int hashCode() {
  return Objects.hash(id);
}
armadilha Campo mutável como chave
Produto p = new Produto(1, "Caneta");
map.put(p, 99);
p.setNome("Lápis"); // muda hashCode!
map.get(p); // retorna null — chave perdida

Use apenas campos imutáveis no hashCode. Prefira String, Integer, UUID como chave.

Fórmula hashCode padrão (Java)

HashMap vs TreeMap: quando usar cada um

Ambas implementam Map<K,V>, mas com trade-offs distintos de complexidade, ordem e requisitos sobre as chaves.

HashMap<K,V>

Tabela hash com encadeamento separado e treeification (Java 8+).

get / putO(1) amortizado
pior caso (colisões)O(n) → O(log n)*
iteraçãoO(n) — sem ordem
memóriamenor
chave requerhashCode + equals
null keypermitido (1)

* após treeification no bucket

TreeMap<K,V>

Árvore rubro-negra balanceada. Mantém chaves em ordem natural ou por Comparator.

get / putO(log n)
pior casoO(log n) garantido
iteraçãoO(n) — ordenada
memóriamaior (ponteiros)
chave requerComparable ou Comparator
null keynão permitido
Guia de decisão rápida
Use HashMap quando:

✓ Velocidade é prioridade
✓ Ordem não importa
✓ Cache, sessões, índices
✓ Chaves são String/Integer

Use TreeMap quando:

✓ Precisa de ordem
✓ firstKey / lastKey / subMap
✓ Range queries
✓ Autocompletar / ranking
